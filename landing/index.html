How it works

Three steps. Your redesign stays untouched.

  1. Paste one line

    A 6 KB script tag, loaded with defer. It never blocks rendering, and every change it makes is wrapped so a bad variant can never break your page. Works on Shopify, Webflow, Next.js, WordPress, and anything that serves HTML.

  2. Approve the variants

    You (or your AI agent, over the API) write the alternates: a gift-shopper hero, a subscribe-and-save strip, a re-sorted catalog. Prism only picks among what you approved. Nothing is generated at request time.

  3. It learns who converts

    Every impression and conversion feeds a Bayesian bandit. Winning variants earn more traffic automatically; losers fade out. You never run a test by hand or watch a significance calculator.

What to expect

Opinionated on purpose

What Prism does

  • Swaps, inserts, reorders, or removes page sections per visitor segment
  • Remembers visitors in a first-party cookie, no fingerprinting, and works with consent banners
  • Shifts traffic to winning variants automatically, per segment
  • Runs after first paint, so your Lighthouse score is untouched
  • Lets your AI agent author and manage variants through the same API you use

What it never does

  • Generate copy or designs on the fly. Only your approved variants ship
  • Block rendering or flash personalized content before paint
  • Require a redesign, a migration, or a CMS
  • Put a model in the request path. Decisions are rules plus statistics
  • Lock your data in. Visitors, variants, and events are yours to export

Integrations

Your segments already exist. Use them.

Prism doesn't ask you to rebuild audiences. Pipe the segments you already trust straight into prism.identify().

Klaviyo + Shopify

// 1) Shopify Liquid, real fields only (login-gated customers)
<script>
{% if customer %}
  prism.identify({
    orders: {{ customer.orders_count }},
    lastOrderDays: {{ 'now' | date: '%s' | minus: customer.last_order.created_at | date: '%s' | divided_by: 86400 }},
    tags: {{ customer.tags | json }}
  });
{% endif %}
</script>

// 2) Klaviyo: forward the identified profile (runs after klaviyo.js)
<script>
var _learnq = window._learnq || [];
_learnq.push(function () {
  var p = this.identify() || {};
  if (p.$email) prism.identify({ klaviyoKnown: true, klaviyoSegments: p.$segments || [] });
});
</script>

Segment

// one line inside your existing identify call
analytics.identify(userId, traits);
prism.identify(traits); // same traits, no dual taxonomy

// conversions flow both ways too
analytics.track("Order Completed", () => prism.convert("#hero"));

React / Next.js: Prism re-decides on client-side navigation and re-applies variants if a hydration pass re-renders a personalized section, verified against App Router. Consent banners: call prism.identify() only after consent. Nothing is tracked before the first call beyond an anonymous cookie.

FAQ

Questions

Will it slow my site down?

No. The snippet loads deferred and applies changes after first paint. Repeat visits are served from a local cache, so the decision costs zero network time.

Do visitors see a flash of the wrong content?

A first-ever pageview can show the default briefly, since we never block paint. Every visit after that applies the cached decision before the frame is visible.

Does it use AI to write my copy?

Only if you want it to. An AI agent can draft variants through the API, but nothing reaches a visitor until it exists as an approved variant. The serving path contains no model at all.

How is this different from an A/B testing tool?

A/B tools split traffic randomly and wait for you to call a winner. Prism splits by visitor segment and continuously reallocates traffic to winners per segment, so the test runs and resolves itself.

What platforms does it work with?

Anything that serves HTML and lets you add a script tag: Shopify, Webflow, Framer, WordPress, Squarespace, Wix, Next.js, custom stacks.
